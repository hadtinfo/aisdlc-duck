# Web 2b-1 — duyệt trên web (kèm R3: nút Duyệt dùng review card) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Với repo ở chế độ `approvals: web`, web là nơi lưu chính submission và approval: dev duyệt / trả lại / mở lại cổng trên trang B (hoặc ở terminal bằng token `approve`), CLI và hook đọc approval qua cache có chữ ký Ed25519 của server, CI hỏi web và FAIL khi cổng chưa duyệt; bản ghi duyệt lưu kèm cờ và giả định dev đã xem (R3).

**Architecture:** Server Spring Boot thêm bảng (V2) cho token có loại, phiên trình duyệt + CSRF, submission (toàn văn artifact), approval, feedback, audit, chế độ theo repo; một khóa Ed25519 ký "trạng thái cổng của một tính năng" thành phong bì `{payload, sig, keyId}`. CLI có `WebGateStore` (implements `GateStore`) đọc phong bì đã ký từ cache `.aisdlc/web/gates/<KEY>.json`, xác minh bằng khóa công khai đã ghim ở `~/.config/aisdlc/web-pubkey`; hook chỉ đọc cache (không gọi mạng), lệnh CLI và tiến trình gửi nền làm mới cache. Chế độ `local` giữ nguyên hành vi giai đoạn 1.

**Tech Stack:** Java 17 (`java.security` Ed25519 có sẵn từ JDK 15, không thêm thư viện), Spring Boot 3.3.5 + JdbcTemplate + Flyway, Postgres 16, picocli, JDK HttpClient, React 18 + TS, Vitest, Playwright 1.49.1 (E2E).

**Spec:** `docs/superpowers/specs/2026-11-03-aisdlc-web-2b-design.md` (§1–3, §5, §7, §9.1, §9.2, §9.5, §10) và `docs/superpowers/specs/2026-11-03-aisdlc-review-design.md` §8 (R3). Phần §4 (tạm dừng, chỉ dẫn), lệnh chờ áp dụng của §3 (accept bước, cho phép file ngoài phạm vi trên web), §9.3, §9.4, §9.6 và diff giữa các lần nộp (review §7) thuộc **plan 2b-2**.

## Quyết định của plan (builder quyết theo spec §8 — dev xem lại)

1. **Bốn loại token**, mỗi token một loại, lưu SHA-256:
   - `login`: do admin cấp bằng `user add` như 2a. **Chỉ loại này** mở được phiên trình duyệt (`POST /api/login`) và đọc các API xem bằng Bearer. Vẫn được nhận ở `/api/ingest/**` để repo 2a chạy tiếp.
   - `ingest`: dev tự tạo ở trang `/me`. Dùng cho `/api/ingest/**` và `/api/cli/**` (đọc trạng thái cổng, nộp, pubkey). Không mở được phiên, không duyệt được.
   - `approve`: dev tự tạo ở `/me`. Chỉ dùng cho `POST /api/gates/**` qua Bearer (đường terminal).
   - `ci`: admin cấp bằng `user ci-token <tên>`. Chỉ dùng `GET /api/ci/approvals`.
   Lý do: nếu token trong `web.json` mở được phiên trình duyệt thì agent đọc được nó sẽ tự lấy cookie + CSRF và tự duyệt (phản mục tiêu §1).
2. **Phiên trình duyệt:** `POST /api/login` với token `login` tạo dòng `sessions` (id ngẫu nhiên, lưu SHA-256, hết hạn 12 giờ); cookie `AISDLC_SESSION` là id phiên (không còn là token thô như 2a); body trả `csrf`. Mọi `POST/PUT/DELETE` bằng phiên phải có header `X-CSRF-Token` khớp phiên, thiếu/sai → 403.
3. **Phong bì ký:** `payload` = base64 của chính bytes JSON server tạo ra; `sig` = Ed25519 trên các bytes đó; CLI xác minh trên bytes nhận được rồi mới parse — không cần chuẩn hóa JSON.
4. **Khóa ký:** file PKCS#8 ở `AISDLC_SIGNING_KEY_FILE` (mặc định `/data/signing-key`, docker volume), tự sinh lần đầu với quyền 600. Đổi khóa: đặt khóa cũ vào `AISDLC_SIGNING_PREVIOUS_KEY_FILE`; `GET /api/cli/pubkey` trả kèm `endorsement` = chữ ký của khóa cũ trên khóa mới (§9.1).
5. **Một phong bì cho cả tính năng** (`FeatureGateState`: chế độ, các submission, approval, feedback, `issuedAt`) thay vì ký từng approval.
6. **Chế độ theo repo trên web:** repo chưa có bản ghi mà CLI báo `approvals: web` (từ `config.yaml`) → server ghim `web`. Chuyển `web → local` chỉ người `lead` làm ở trang `/repos`. CLI: phong bì hợp lệ nói `web` thì là web bất kể `config.yaml`; `config.yaml` nói `web` mà chưa có phong bì → vẫn coi là web (chưa có approval nào, an toàn).
7. **Trạng thái hiển thị trên web** của repo chế độ web lấy theo dữ liệu server (approval/submission trong DB đối chiếu `currentHash` của snapshot mới nhất), không chờ CLI gửi snapshot mới.
8. **Snapshot thêm trường `tree`** (cây code hiện tại trừ thư mục tính năng, như `evaluatedTree`), chỉ khi cổng REVIEW không còn khóa, để server kiểm luật duyệt REVIEW.
9. **Feedback** (trả lại / mở lại trên web) nằm trong phong bì; CLI khi làm mới cache ghi các mục mới vào `feedback.md` (theo id, không ghi trùng) để agent đọc như giai đoạn 1. Đường chỉ dẫn tức thời qua hook là của 2b-2.
10. **Ở chế độ web, `step accept` và `scope allow` ở terminal vẫn ghi cục bộ như giai đoạn 1** (trạng thái bước nằm trong repo); nút tương ứng trên web là của 2b-2.
11. **R3:** bản ghi duyệt lưu `flags` (mã + mức các cờ HIGH/WARN của review card lúc duyệt) và `assumptionsSeen` (văn bản các giả định dev đã tick). Bước xác nhận trên web luôn liệt kê cờ HIGH/WARN và số giả định chưa tick; duyệt từ terminal lưu `flags` từ thẻ CLI vừa in và `assumptionsSeen: []`.

## Global Constraints

- Không thêm thư viện mới (Maven hay npm). Ed25519 dùng `java.security.KeyPairGenerator/Signature` với tên thuật toán `"Ed25519"`.
- Chế độ `local` (mặc định) giữ nguyên hành vi giai đoạn 1 và 2a: mọi test hiện có phải xanh, E2E `WEB=0` và `WEB=1` không đổi kết quả.
- Hook PreToolUse/PostToolUse **không gọi mạng**; độ trễ hook giữ quanh mức 2a (~0,3 giây). Lệnh CLI gọi web: nộp timeout 5 giây, đọc trạng thái timeout 2 giây rồi dùng cache.
- Không bao giờ ghi token ra log, stdout của hook, báo cáo hay audit (chỉ ghi id token).
- Bảng `audit` không cho `UPDATE`/`DELETE` (trigger chặn). Mỗi thao tác ghi (duyệt, trả lại, mở lại, tạo/thu hồi token, đổi chế độ, xác nhận nhập, nộp) ghi một dòng: `at, login, ip, channel (web|terminal|cli|admin), action, repo_id, feature_key, target, detail jsonb`.
- Quyền thao tác cổng: chủ tính năng (owner theo `BoardRules.owner`) hoặc user `role = lead`; kiểm phía server.
- Thông báo cho người dùng bằng tiếng Việt, cùng giọng giai đoạn 1.
- Mã thoát CLI giữ: `0` OK, `1` có phát hiện/FAIL, `2` dùng sai/thiếu điều kiện, `3` không phải dev.
- `mvn -q verify`, `e2e/run-e2e.sh`, `WEB=0 e2e/run-e2e.sh` xanh sau mỗi task.

## Review Focus

1. **Agent dùng token trong `web.json` để tự duyệt:** token `ingest` gọi `/api/login`, `/api/gates/**` → 401/403; hook chặn mọi tool (kể cả Read/Grep/Glob/Bash) chạm `~/.config/aisdlc/**`. → test trong Task 2 và Task 6.
2. **Cache bị sửa / chép cache cũ / khóa công khai bị thay:** approval có chữ ký sai, hash không khớp nội dung hiện tại, phong bì của repo/tính năng khác, hoặc khóa không được khóa đang ghim ký → coi như không có approval, hook chặn sửa code. → test Task 1 và Task 6.
3. **Web chết giữa chừng:** cổng đã duyệt (cache hợp lệ) vẫn cho sửa code; `submit` báo lỗi rõ ràng và không ghi gì; `approve` ở terminal báo lỗi, không ghi `gates.json`. → test Task 6, E2E Task 8.

5. **Snapshot/phiên cũ:** đăng xuất rồi dùng lại cookie → 401; CSRF của phiên khác → 403; token đã thu hồi → 401 ngay. → test Task 2.
