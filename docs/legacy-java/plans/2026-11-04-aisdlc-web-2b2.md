# Web 2b-2 — tạm dừng, chỉ dẫn, accept bước / cho phép file trên web, diff giữa các lần nộp (R3) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dev tạm dừng / cho chạy tiếp agent và gửi chỉ dẫn từ màn C; accept bước và cho phép file ngoài phạm vi từ trang B qua lệnh chờ áp dụng có chữ ký; trang B cho thấy thay đổi so với lần nộp trước cùng trạng thái từng góp ý; event mang `sessionId`; siết các heuristic hook còn treo từ 2b-1.

**Architecture:** Server lưu trạng thái điều khiển theo tính năng (cờ tạm dừng, chỉ dẫn, lệnh chờ áp dụng) và ký thành phong bì `FeatureControl` bằng khóa Ed25519 của 2b-1. Tiến trình gửi nền và lệnh CLI tải phong bì về `.aisdlc/web/control/<KEY>.json`; hook chỉ đọc file này (không gọi mạng): PreToolUse chặn khi tạm dừng, PostToolUse trả chỉ dẫn qua `additionalContext`, mọi lần CLI/hook dựng tính năng thì áp dụng lệnh chờ còn khớp trạng thái kỳ vọng. Kết quả giao/áp dụng đi ngược lên web bằng event (outbox của 2a), nên hook vẫn không gọi mạng. Diff giữa các lần nộp tính phía server từ toàn văn artifact đã lưu ở 2b-1.

**Tech Stack:** như 2b-1 — Java 17, Spring Boot 3.3.5 + JdbcTemplate + Flyway, Postgres 16, picocli, JDK HttpClient, React 18 + TS, Vitest, Playwright 1.49.1. Không thêm thư viện.

**Spec:** `docs/superpowers/specs/2026-11-03-aisdlc-web-2b-design.md` §3 (accept bước, cho phép file), §4, §7, §9.3, §9.4, §9.6; `docs/superpowers/specs/2026-11-03-aisdlc-review-design.md` §7 (diff giữa các lần nộp). Việc treo từ 2b-1: ledger `scratchpad/sdd-ledger-2b1.md`, mục "parked".

## Quyết định của plan (builder quyết theo spec §8 — dev xem lại)

1. **Điều khiển chạy ở cả hai chế độ duyệt** (`local` và `web`), miễn máy dev đã `aisdlc web login` (có khóa ghim). Lý do: tạm dừng / chỉ dẫn / accept bước không đụng tới nơi lưu approval. Chưa `web login` thì lệnh chờ không bao giờ áp dụng được; web hiện "chờ áp dụng" tới khi hết hạn.
2. **Ai thao tác:** chủ tính năng hoặc `lead` (cùng luật 1 của 2b-1). Chỉ qua **phiên trình duyệt + CSRF**; Bearer mọi loại (kể cả `approve`) gọi `POST /api/control/**` → 403. Đường terminal đã có sẵn (`aisdlc step accept`, `scope allow`), không cần token.
3. **Đường ngược lên web là event**, không phải API riêng: hook không gọi mạng nên ghi event vào outbox 2a. Loại event mới: `INSTRUCTION_DELIVERED` (`detail` = id), `ACTION_RESULT` (`detail` = JSON `{"id":..,"status":"APPLIED|STALE","reason":..}`), `SCOPE_DENIED` (`path`, `step`: hook vừa chặn ghi ngoài phạm vi). Server cập nhật bảng điều khiển trong cùng giao dịch ghi event.
4. **Hợp đồng event v2:** lô có `"version": 2`; mỗi event thêm `sessionId` tùy chọn (≤ 100 ký tự, lấy từ `session_id` của input hook; lệnh CLI không có). Server nhận cả lô v1 (không có `version`) lẫn v2; cột `events.session_id`.
5. **Sổ cục bộ** `.aisdlc/web/control/<KEY>.local.json` = `{"delivered":[id...],"results":{"<id>":"APPLIED|STALE"}}`, ghi dưới khóa file `.aisdlc/web/control/control.lock`. Đảm bảo mỗi chỉ dẫn giao **tối đa một lần** trên một máy và mỗi lệnh chờ chỉ áp dụng/báo một lần. Web đánh dấu "đã giao" khi event tới.
6. **Cờ hộp thư** `.aisdlc/web/control/inbox` (file rỗng): có khi phong bì đang có chỉ dẫn chưa nằm trong `delivered`. PostToolUse mở cho **mọi tool**; `plugin/bin/aisdlc` thoát ngay (không JVM) với tool không ghi khi không thấy cờ này ở gốc repo.
7. **Tạm dừng:** PreToolUse chặn mọi tool ghi (`Edit|Write|MultiEdit|NotebookEdit|Bash`) của tính năng đang làm, trước mọi luật khác (trừ luật `~/.config/aisdlc`). Lý do đúng câu spec: `Dev đã tạm dừng tại web: <tên>. Dừng lại và chờ.` Stop không chặn khi đang tạm dừng (kể cả bước đang IN_PROGRESS). Tool bị chặn không sinh PostToolUse, nên **hook tự mở `web flush`** khi chặn vì tạm dừng, tối đa một lần mỗi 5 giây (mtime file `.aisdlc/web/control/spawned`) — không thế thì cờ tạm dừng không bao giờ được làm mới.
8. **Lệnh chờ áp dụng** (`pending_actions`), hết hạn 7 ngày:
   - `ACCEPT_STEP`: server chỉ nhận khi snapshot mới nhất có bước đó `AWAITING_DEV`, và ghi `endTree` của bản ghi bước làm trạng thái kỳ vọng. Máy dev áp dụng khi `steps.json` có bước đó `AWAITING_DEV` với cùng `endTree` → `StepService.accept(step, "<login> (web)")`. Đã `ACCEPTED` cùng `endTree` → coi như APPLIED (idempotent). Khác → STALE với lý do.
   - `ALLOW_SCOPE`: server nhận khi bước đó `IN_PROGRESS` hoặc `AWAITING_DEV` và `path` là đường dẫn tương đối hợp lệ (không rỗng, không `/` đầu, không `..`, không `\`, không bắt đầu bằng `.aisdlc/`, ≤ 500 ký tự). Máy dev áp dụng khi bước đó có trong thiết kế → `ScopeExtras.add(path, "<login> (web)", at)`. Không có trạng thái kỳ vọng `endTree` (cho phép một file không phụ thuộc cây code).
   - Bấm lại cùng `(kind, step, path)` khi còn PENDING → trả lệnh cũ, không tạo mới. Không có nút hủy (hết hạn 7 ngày).
9. **Trả lại / mở lại cổng trên web** sinh thêm một chỉ dẫn (`source = feedback`): `Cổng <GATE> bị trả lại bởi <login>: <comment>` (mở lại: `được mở lại bởi`). `feedback.md` vẫn ghi như 2b-1.
10. **Diff giữa các lần nộp (R3)** chỉ có ở repo chế độ `web` (web là nguồn duy nhất, review §7). Đường tạm cục bộ của R1 (`.aisdlc/run/<KEY>/submissions/`) chưa từng làm và **không làm**: repo `local` không có mục này.
11. **Khớp góp ý ↔ thay đổi (mức nhẹ):** góp ý = các feedback của cổng có `at` nằm giữa lần nộp n-1 và lần nộp n. "Được nhắc" = đường dẫn đầy đủ hoặc tên file của artifact xuất hiện trong comment (không phân biệt hoa thường), hoặc tiêu đề markdown (`#`…`######`, ≥ 3 ký tự) của bản n-1 xuất hiện trong comment. Trạng thái: không nhắc gì → `UNMATCHED` ("không rõ mục nào"); có file/mục được nhắc mà đã đổi → `RELATED_CHANGED` ("có thay đổi liên quan"); còn lại → `NO_CHANGE_SEEN` ("chưa thấy thay đổi"). Mục = từ dòng tiêu đề tới tiêu đề kế tiếp cùng cấp hoặc cấp cao hơn.
12. **Phong bì chế độ có `issuedAt`;** CLI chỉ ghi `mode.json` và `control/<KEY>.json` khi `issuedAt` mới ≥ bản đang có (cùng luật cache cổng của 2b-1). Chống chép lại phong bì cũ bằng mốc ngoài repo vẫn để sau (mô hình §7b).
13. **Heuristic hook siết thêm** (việc treo 2b-1): `env` chỉ có cờ/gán biến mà không có lệnh; đọc `/proc/*/environ` bằng Read/Grep/Glob; `set(` / `env(` kiểu gọi hàm không còn bị chặn nhầm; đường dẫn có `\` (`ai\sdlc`, `.con\fig`) được xét thêm bản bỏ `\`. Các việc treo khác (định dạng hash, N+1 ở bảng, CSRF cũ khi đăng nhập tab khác, panel nhấp nháy) để sau.

## Global Constraints

- Không thêm thư viện mới (Maven hay npm).
- Hook PreToolUse/PostToolUse/Stop/SessionStart **không gọi mạng**. Độ trễ hook giữ mức 2b-1; tool đọc không ghi (Read/Grep/Glob/…) ở PostToolUse thoát trong shell khi không có cờ `inbox`.
- Không bao giờ ghi token ra log, stdout của hook, báo cáo hay audit.
- Chỉ dẫn: 1–2000 ký tự sau khi trim; không sửa, không xóa sau khi gửi.
- Bảng `audit` chỉ thêm. Mỗi thao tác điều khiển ghi một dòng, channel `web`: `control.pause`, `control.resume`, `control.instruction` (detail `{id, length}` — không chép nội dung), `control.action` (detail `{id, kind, step, path}`).
- Thông báo tiếng Việt, cùng giọng giai đoạn 1. Mã thoát CLI giữ `0/1/2/3`.
- Chế độ `local` và repo chưa `web login` giữ nguyên hành vi trước: mọi test hiện có xanh.
- `mvn -q verify`, `plugin/test/plugin-files-test.sh`, `e2e/run-e2e.sh`, `WEB=0 e2e/run-e2e.sh` xanh sau mỗi task (task chỉ đụng web/UI chạy ít nhất `mvn -q verify`).

```sql
CREATE TABLE feature_control (repo_id text NOT NULL, feature_key text NOT NULL, paused boolean NOT NULL DEFAULT false,
    paused_by text, paused_at timestamptz, PRIMARY KEY (repo_id, feature_key));
CREATE TABLE instructions (id bigserial PRIMARY KEY, repo_id text NOT NULL, feature_key text NOT NULL,
    by_login text NOT NULL, at timestamptz NOT NULL DEFAULT now(),
    text text NOT NULL CHECK (char_length(text) BETWEEN 1 AND 2000),
    source text NOT NULL CHECK (source IN ('web', 'feedback')), feedback_id bigint REFERENCES feedback(id),
    delivered_at timestamptz);
CREATE INDEX instructions_feature ON instructions (repo_id, feature_key, id);
CREATE TABLE pending_actions (id bigserial PRIMARY KEY, repo_id text NOT NULL, feature_key text NOT NULL,
    kind text NOT NULL CHECK (kind IN ('ACCEPT_STEP', 'ALLOW_SCOPE')), step text NOT NULL, path text, end_tree text,
    created_by text NOT NULL, created_at timestamptz NOT NULL DEFAULT now(), expires_at timestamptz NOT NULL,
    status text NOT NULL DEFAULT 'PENDING' CHECK (status IN ('PENDING', 'APPLIED', 'STALE')),
    resolved_at timestamptz, reason text);
CREATE INDEX pending_actions_feature ON pending_actions (repo_id, feature_key, id);
ALTER TABLE events ADD COLUMN session_id text;
```
HTTP:
- `POST /api/control/pause {repo, feature, paused: bool}` → view. Bật lại khi đã bật thì giữ `paused_by/at` cũ.
- `POST /api/control/instructions {repo, feature, text}` → view. Trim; rỗng hoặc > 2000 → 400 `{"error":"Chỉ dẫn phải từ 1 đến 2000 ký tự"}`.
