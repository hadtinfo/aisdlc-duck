# Song ngữ EN/VI — Đợt 4 (web) Implementation Plan

**Goal:** Web theo ngôn ngữ người xem: cột `users.locale`, `GET /api/me` trả `locale`, `PUT /api/me/locale`; chữ do
server sinh (lỗi API, inbox, nhãn tự duyệt, lý do đã lưu) dịch theo locale của request; UI React có từ điển vi/en, bộ
chọn EN/VI ở `UserMenu` và trang Login.

**Architecture:**
- Locale của request nằm trên `context` (`httpx.WithLocale` / `httpx.LocaleFrom`). Middleware gốc đặt locale từ
  `Accept-Language`; middleware xác thực ghi đè bằng `users.locale` khi đi bằng phiên và user đã chọn.
- `httpx.Text` = khóa tiếng Việt + đối số (`httpx.T`, `httpx.Tf`), dịch lúc ghi phản hồi. `ApiError` giữ `Text`;
  `WriteError(w, r, err)` dịch theo `LocaleFrom(r.Context())`. `Message` vẫn là chuỗi tiếng Việt (log, `Error()`).
- Code sâu (overlay, inbox) lấy locale từ ctx hoặc nhận `i18n.Locale` tường minh; không dùng `i18n.T`/`Tf`/`Default`.
- Nhật ký vận hành, lỗi khởi động và lệnh quản trị `aisdlc-web user …` (không thuộc request nào) dùng
  `httpx.OpLocale()` = `AISDLC_LOCALE` của tiến trình (thiếu/sai → vi).
- Chuỗi đã lưu DB (`ImportReason`, `pending_actions.reason`) giữ tiếng Việt, đăng ký khóa bằng `i18n.VI.T(...)`, dịch
  lúc hiển thị bằng `loc.T(stored)`.
- UI: `web/ui/src/i18n/{vi,en,index}.ts`, `en: Record<keyof typeof vi, string>`; `t(key, params)`, `useT()`,
  `LocaleProvider`; chọn: server (đã đăng nhập, đã chọn) → `localStorage` → `navigator.language`.

**Global Constraints:** locale vi ra đúng byte như cũ (test hiện có giữ kỳ vọng); mã lỗi/khóa JSON/tên cổng/lệnh CLI
không dịch; không sửa gói của đợt 2/3, `en.go`, CHANGELOG; không dependency mới.

**Review Focus:** không lẫn locale giữa request (không biến toàn cục cho locale request); `Accept-Language` dịu
(tag đầu tiên theo q có primary subtag vi|en; không có → vi); `PUT /api/me/locale` chỉ nhận vi|en, cần phiên + CSRF.

4. **Test EN phía server** — inbox (`board.Inbox(snap, i18n.EN)`), lỗi API qua phiên `locale=en` và token +
