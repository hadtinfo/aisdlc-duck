Plugin Claude Code · Go · PostgreSQL

Agent viết code. Dev duyệt từng cổng.

AISDLC là quy trình phát triển tính năng có cổng chất lượng, dành cho đội làm service Go với agent Claude Code. Agent soạn BRD, thiết kế, case và code; dev duyệt từng cổng. Hook của plugin chặn agent đi tắt, và CI kiểm lại mọi merge request.

Cách hoạt động

Một tính năng đi qua năm cổng. Cổng trước được duyệt thì cổng sau mới mở. Tài liệu đã duyệt bị khóa theo hash; muốn sửa, dev phải mở lại cổng đó.

Cổng duyệt

Agent chỉ được ghi code sản phẩm khi BRD, Thiết kế và Case đã được duyệt. Tài liệu đã duyệt bị khóa theo hash.

Code từng bước

Mỗi bước S1…Sn khai báo phạm vi file (glob) và ngân sách (số file, số dòng). Ghi ngoài phạm vi bị chặn, trừ khi dev cho phép từng file.

Case trước code

Case HTTP, DB, message, stub được viết và khóa trước, và phải có case fail lúc nộp. Harness chạy case dạng black box trên service thật, Postgres (và Kafka) dựng bằng Docker.

Eval và review

Build, go test, bộ case, coverage dòng mới và review độc lập bằng subagent, ghi vào eval/report.md. CI chạy lại trên MR.

Cài đặt và gắn vào service

Cần Linux hoặc macOS, Go, Docker (harness dựng Postgres/Kafka), git và Claude Code.

  1. Cài plugin trên máy dev

    Script build aisdlc và aisdlc-harness cho máy của bạn và tạo link ~/.local/bin/aisdlc (thêm vào PATH).

    git clone https://github.com/hadtinfo/aisdlc-duck.git ~/aisdlc
~/aisdlc/plugin/install.sh

    Rồi trong Claude Code:

    /plugin marketplace add ~/aisdlc
/plugin install aisdlc@aisdlc

    Máy không có Go? Tải bundle plugin dựng sẵn ở GitHub Releases, giải nén rồi trỏ /plugin marketplace add vào thư mục đó.

  2. Gắn vào repo service (MR riêng)

    Ở gốc một service Go có go.mod, cmd/<tên>/main.go và migration goose:

    aisdlc setup --preset generic     # hoặc --preset banking
git status --short

    Lệnh tạo aisdlc/config.yaml, aisdlc/risk-policy.yaml, aisdlc/gitlab-ci.aisdlc.yml, thêm mục AISDLC vào CLAUDE.md và bỏ qua .aisdlc/. Kiểm tra mục service và migrations trong config.

  3. Kiểm tra service đáp ứng hợp đồng của harness

    • Đọc cổng và URL DB (và Kafka brokers) từ các biến khai báo trong service.env.
    • service.healthPath trả 2xx khi sẵn sàng.
    • Thoát gọn khi nhận SIGTERM (nếu không, coverage dòng mới là N/A).
    • Migration goose đặt tên NNNNN_ten.sql, có -- +goose Up.

  4. Làm một tính năng

    /aisdlc:init PAY-123  →  /aisdlc:brd  →  /aisdlc:design  →  /aisdlc:cases
/aisdlc:step S1  …  /aisdlc:step Sn  →  /aisdlc:review

    Sau mỗi chặng, dev duyệt ở terminal riêng: aisdlc approve design, aisdlc step accept S1… Merge MR setup trước, bật CI ở MR sau.

Ví dụ: PAY-1 “Kiểm tra hạn mức ngày”

Cùng kịch bản mà test E2E chạy trên service mẫu e2e/fixture-service. Chính sách rủi ro của repo xếp mọi thứ có chữ “hạn mức” vào mức high, mức này yêu cầu case gửi trùng và một bất biến DB.

1 · Khởi tạo và soạn BRD

claude code · agent
$ aisdlc init PAY-1 --title "Kiểm tra hạn mức ngày"
Đã tạo tính năng PAY-1 (luồng FULL): Kiểm tra hạn mức ngày
  aisdlc/features/PAY-1/brd.md
  aisdlc/features/PAY-1/design.md
  aisdlc/features/PAY-1/design.yaml
  aisdlc/features/PAY-1/cases.yaml
Tiếp theo: soạn brd.md rồi chạy `aisdlc submit brd`.

$ aisdlc submit brd
Rủi ro tạm (từ khóa): high
Đã nộp cổng BRD, không có phát hiện.

2 · Dev duyệt — ở terminal của mình

Agent thử duyệt thì bị từ chối (exit 3), và hook chặn ghi code khi cổng chưa mở. Dev đọc thẻ review rồi gõ lại feature key:

terminal của dev
$ aisdlc approve brd
Review card — PAY-1 · cổng BRD
Cờ đỏ (2)
  [WARN] BRD_RULE_NO_ID: 4 quy tắc nghiệp vụ không có ID BR-n …
Gõ lại feature key (PAY-1) để xác nhận: PAY-1
Đã duyệt cổng BRD bởi dev (hash …).

Muốn trả lại: aisdlc reject brd -m "Đánh ID BR-n cho từng quy tắc" — góp ý ghi vào feedback.md.

3 · Thiết kế: bước kèm phạm vi và ngân sách

steps:
  - id: S1
    title: Kiểm tra request
    scope: ["internal/limit/web/**", "cmd/server/routes.go"]
    budget: { files: 2, lines: 60 }
  - id: S2
    title: Tính hạn mức theo bảng daily_limit
    scope: ["internal/limit/**", "db/migrations/**"]
    budget: { files: 3, lines: 80 }
invariants:
  - name: Số đã dùng không vượt hạn mức
    sql: "SELECT account_id FROM daily_limit WHERE used_amount < 0 OR used_amount > limit_amount"
impact: { level: medium, labels: [schema-change] }

submit design chạy thử migration nháp trên Postgres thật và tính mức rủi ro đầy đủ. Thẻ review báo SCOPE_OVERLAP (S1 và S2 cùng chạm internal/limit/web/**) và SCOPE_MATCHES_OLD_MIGRATION — xem ảnh cổng Thiết kế bên dưới.

4 · Case được đối chiếu với mức rủi ro

claude code · agent
$ aisdlc submit cases
RISK_REQ: Mức high yêu cầu Case gửi trùng: … POST /api/v1/limits/check
(exit 1)

Agent thêm case C7 (when.repeat: 2, kiểm used_amount không đổi) rồi nộp lại. Chưa có code nên một số case fail — điều này là bắt buộc. Sau khi duyệt, cases.yaml bị khóa; hook chặn cả sed -i trên file này.

5 · Code từng bước, trong phạm vi

claude code · agent
$ aisdlc step finish S1
2/2 pass                                        # S1 → AWAITING_DEV, agent dừng

$ aisdlc step finish S2
Ngoài phạm vi: README2.txt                      # exit 1

Dev quyết: xóa file, hoặc aisdlc scope allow README2.txt. Chạy lại, S2 báo 7/7 pass, dev chạy aisdlc step accept S2.

6 · Eval, review độc lập, MR

/aisdlc:review chạy aisdlc eval (dòng đầu eval/report.md: Eval PAY-1: ĐẠT), gọi subagent aisdlc-reviewer chấm năm tiêu chí rồi nộp. Sau aisdlc approve review, mở MR: job CI chạy aisdlc eval --ci. Ai sửa cases.yaml sau khi duyệt thì CI fail ở CASES_LOCKED.

Web (tùy chọn)

aisdlc-web thêm bảng tính năng, theo dõi agent trực tiếp, duyệt cổng trên trình duyệt, tạm dừng agent, gửi chỉ dẫn, accept bước và cho phép file.

Chạy thử trên máy

docker build -f Dockerfile.web -t aisdlc-web .
docker run -d --name aisdlc-db -e POSTGRES_USER=aisdlc -e POSTGRES_PASSWORD=doi-mat-khau \
  -e POSTGRES_DB=aisdlc postgres:16-alpine
docker run -d --name aisdlc-web -p 127.0.0.1:8080:8080 --link aisdlc-db \
  -e AISDLC_DB_URL=postgres://aisdlc-db:5432/aisdlc -e AISDLC_DB_PASSWORD=doi-mat-khau \
  -v aisdlc-data:/data aisdlc-web

docker exec aisdlc-web /aisdlc-web user add dev "Tên Dev" --email dev@example.com
# đăng nhập bằng token vừa in, tạo token ingest ở trang /me, rồi:
aisdlc web login

Đặt approvals: web trong aisdlc/config.yaml để bản ghi duyệt nằm trên server; CI khi đó hỏi web thay vì tin repo. Triển khai thật: vận hành web.

Chính sách rủi ro

Mỗi repo khai báo thang mức, rule nhận diện tính năng rủi ro (từ khóa, đường dẫn, bảng, endpoint, nhãn) và yêu cầu theo mức. Agent chỉ được nâng mức, không được hạ. Mức thấp có thể tự duyệt lần nộp sạch — Review luôn do dev duyệt.

flow:
  low:    { brd: auto,   design: auto,   cases: auto,   step: auto }
  medium: { brd: manual, design: manual, cases: manual, step: auto }
  high:   { brd: manual, design: manual, cases: manual, step: manual }
Yêu cầuÝ nghĩa
rule-pos-negMỗi quy tắc BR-n có case happy và case error/boundary
idempotentMỗi endpoint ghi có case when.repeat ≥ 2
concurrentÍt nhất một case when.parallel ≥ threads
invariantThiết kế khai báo bất biến SQL phải trả 0 dòng
coverageCoverage dòng mới ≥ min%
sql-zeroTruy vấn của dự án phải trả 0 dòng sau bước cuối

Mô hình an toàn

AISDLC giả định agent có thể nhầm, không phải cố tình tấn công. Hook chặn lỗi vô ý trên máy dev; protected branch cùng job eval trên CI mới là lớp thực thi thật.

Hook PreToolUse

Chặn ghi file trạng thái và tài liệu đã duyệt, ghi ngoài phạm vi bước, đụng tới ~/.config/aisdlc, và lệnh in biến môi trường.

Hook không gọi mạng

Hook chỉ đọc cache ký Ed25519 bởi server; khóa công khai được ghim trên máy dev.

CI kiểm lại

CI fail khi cổng chưa duyệt, nội dung lệch hash đã duyệt, hoặc code đổi sau khi duyệt Review.

Chặn ghi qua Bash chỉ là heuristic. Các cách vượt đã biết nằm ở mục 8.1 của hướng dẫn sử dụng. Báo lỗ hổng: xem SECURITY.md.
